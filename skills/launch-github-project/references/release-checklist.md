# Release checklist

## Local readiness

- Scope and primary project type are explicit.
- Repository status and intended files are understood.
- Public documentation has no placeholders or private paths.
- Secret and privacy checks have run.
- License and third-party notices match the material.
- Quick start was tested from a clean path when applicable.
- Native tests, Evals or reproduction steps have results.
- Links and visual assets resolve.
- Claims distinguish verified, partial and unverified.
- Package contents were listed and extracted successfully.
- Public-surface blockers are zero and every warning was reviewed individually.
- Asset rights have a final recorded state; no public file says permission is still pending.
- Fixture or schema checks are not presented as product-performance percentages.
- Public behavior scores link to complete sanitized raw outputs and limitations.
- Git authors, contributors, recent commit messages and nested repositories were reviewed.

## Remote decision gate

Before remote publication, confirm together:

- account or organization;
- exact repository name;
- public or private visibility;
- default branch and files to include;
- license;
- initial version and Release status;
- whether external announcements are in scope.
- whether maintainer plans, launch drafts and raw evaluation runs belong in the public tree.

## After publication

Open the repository as an unsigned visitor when possible. Verify the first screen, images, links, clone or download path, Topics, social preview and Release asset. Confirm the visible contributors and recent history are intended. Do not call the launch complete based only on a successful push.
